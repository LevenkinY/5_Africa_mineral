# 数据管理说明

本项目的数据管理目标是：原始数据可追溯，清洗过程可复现，最终分析表可解释。

## 数据分层

建议后续建立以下目录：

```text
data/
  raw/          # 原始数据，不手工修改
  interim/      # 中间清洗结果
  processed/    # 分析模型直接使用的数据
  external/     # 外部数据下载说明、授权说明或轻量索引
```

## 原始数据

原始数据应尽量保持下载时的状态，不手工编辑。每个数据源应配套一个说明文件，记录：

- 数据名称
- 机构或作者
- 下载链接
- 下载日期
- 版本号
- 许可或使用限制
- 主要字段
- 与本研究的用途

## 敏感与受限数据

以下材料不应提交到公开 GitHub 仓库：

- 商业数据库导出文件
- 需要账号授权的数据下载件
- 未经许可的访谈录音、逐字稿或个人联系方式
- 含受访者身份、联系方式、精确住址等个人信息的数据
- API token、账号密码、cookie、私钥

如必须记录相关来源，应提交元数据说明，而不是提交原始文件。

## 可复现要求

每个处理后数据表都应尽量能由脚本从原始数据生成。脚本需说明输入、输出和关键处理规则。

建议命名：

```text
scripts/01_download_sources.py
scripts/02_clean_trade_data.py
scripts/03_merge_country_panel.py
scripts/04_build_figures.py
```

## 数据字典

每张分析表应配套数据字典，至少包含：

- 字段名
- 字段含义
- 单位
- 数据来源
- 缺失值处理
- 是否经过标准化或转换

## 引用

正式写作时，所有数据库都需要在正文、脚注或附录中说明来源。对于持续更新的数据，应记录访问日期。
